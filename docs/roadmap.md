# 实施阶段与验收

更新日期：2026-10-06  
状态：设计阶段，尚未实现和验证

## MVP 必须形成的闭环

多 Host 接入 → 状态与上下行 → 文件、终端、Docker 和项目 Git 查询 → 中心 AI 主动调用读取工具 → 有证据的分析与建议 → 用户可通过现有面板发起明确操作 → 必要任务和审计。

AI Observe/Suggest 是首版交付要求。仅有面板、聊天框或模拟工具不算 MVP 完成。幂等、限流、权限检查、身份隔离、查询记录和任务恢复从首个远程操作开始贯穿。

## 2026-10-06 开工检查

文档已按整体架构、单功能和共用机制拆分。四大指标、前端视觉、AI 核心地位、Responses API、Linux Agent 与后续 Kubernetes 范围已明确，可以开始独立前端切片，无需等待全部部署信息。

首个切片只实现[前端架构](design/frontend.md)所列仪表台与演示状态，不改变阶段一至三的 MVP 验收范围。用户已允许安装前端依赖和启动仅本机预览进行视觉验证；不包含连接数据库或操作真实服务器。

| 门槛 | 尚缺内容 | 影响 |
| --- | --- | --- |
| 前端独立切片 | 无业务阻塞；依赖版本与本机兼容性需安装验证 | 可以开工，使用明确标记的样本 |
| 中心与 Agent 接入 | 正式 API/协议、认证会话、注册撤销、schema、采样及缓存界限 | 实现远程链路前逐项形成契约，不能拿前端样本充当协议 |
| 首次真实部署 | OS/架构、中心位置、TLS 域名、端口可达性、执行身份、业务保护范围、数据库与 Redis 环境 | 不阻塞前端；阻塞真实部署验收 |
| AI 真实验收 | 提供方、模型、秘密注入、外发许可、工具预算与样本评分 | 不阻塞界面；阻塞 AI 能力完成声明 |
| 后续功能 | 集群权限、告警通知、编辑快照与升级策略 | 不阻塞首版独立模块 |

跨 Workspace 共享不是首版待实现项，初期禁止共享；不因未来共享问题阻塞单 Workspace 开发。协议与存储相关数值需在对应后端切片确定，不强行在视觉文档中作无依据的承诺。

## 分阶段交付

| 阶段 | 功能 | 验收边界 |
| --- | --- | --- |
| 一：基础接入，MVP | 中心、PostgreSQL、Redis、Agent 身份、心跳、能力、基础指标与短窗口 | 两台真实机器、撤销凭据、断线重连、统计口径与身份隔离 |
| 二：日常操作，MVP | 文件浏览传输、终端、Docker 查询及基本操作、项目登记和 Git 查询、工具与任务审计 | UI 到真实 Agent，权限拒绝、正确目标、数据传输、重复消息和任务查询 |
| 三：AI 分析与建议，MVP | 实际模型接入、Observe/Suggest、服务器分析、容器日志解释、项目状态比较和部署候选建议 | 实际工具证据、失败与信息缺口、只读边界、敏感数据保护及建议质量 |
| 四：受控操作扩展 | Compose、代理诊断、服务安装、配置快照、Git 写操作、批量任务及逐步开放的 AI Execute | 各操作授权、前置状态变化、冲突、审批有效性、失败恢复与秘密保护 |
| 五：持续运维与集群 | 历史趋势、告警、已有 Kubernetes 集群只读查询、Agent 升级 | 页面关闭后采集、异常和恢复、集群权限、升级兼容和失败处理 |
| 六：后续集群操作 | Kubernetes 写操作与集群生命周期管理 | 单独定义网络、存储、业务影响、授权与恢复验收 |

阶段一至三共同组成 MVP；第四阶段之后不阻塞首版建议能力。跨功能依赖按实际工具成熟度开放，不展示不可用按钮伪装成功能完成。

## MVP 不包含

AI 自主写操作、Git fetch/pull/提交/推送等写任务、Kubernetes 接入、完整 Compose 部署、专项代理探测、安装平台、完整配置版本系统、批量灰度升级及独立 CMDB。

AI 可以解释已有日志中的下载错误，但在专项探测未实现前不能声称实际验证代理或网络。Git 查询依据本地仓库状态，不自动同步远端。

## Redis 与基础可靠性

MVP 同时覆盖重复受理、重复投递、幂等冲突、限流拒绝、Agent 执行不确定及 Redis 故障，具体机制见[可靠性设计](design/reliability.md)。不以锁获取成功代替外部副作用验证。

## 验证原则

前端按[已确认界面方向](design/ui.md)实现：四项指标首屏突出、非同质四卡、按状态用色、右侧 AI 和底部终端。视觉验收覆盖桌面、移动端、数据缺失、失联、减少动态、键盘操作和真实目标隔离；功能与视觉均未实现前不标记完成。

定向单元和协议测试覆盖局部逻辑，真实集成验证主机操作；端到端必须走实际 UI/API、模型（AI 场景）、工具、Agent 和目标系统。测试替身不能代替最终链路。

验收前定义场景、成功条件、样本来源、排除、超时、重试和评分规则。分别报告有效样本、已完成可评分输出、成功、失败与未执行；设施失败单列。AI 工具调用正确与建议质量分别评估，不混为一个通过标志。

性能测量记录系统配置、版本、目标数量、数据量、采样周期与持续时间。分别测量空闲、文件传输、日志跟随、部署及 AI 调查对中心和 Agent 的影响。

当前全部文档仍是设计，未实现，未连接真实服务器或数据库，未执行任何运行验收。

## 五项核心设计

| 优先项 | 已有方向 | 实施前待确认 |
| --- | --- | --- |
| 资源模型 | Host 与 Cluster 独立；Docker 是主机能力；初期单 Workspace | Host 跨 Workspace 共享规则、资源标识、授权归属与关联依据 |
| Agent 通信协议 | 主动认证长连接、结构化 Action、执行状态同步 | WSS 与 gRPC 选型、消息格式、兼容范围、确认语义与缓存上限 |
| Task 执行模型 | Task → Step → 目标执行 → Attempt | 依赖与批量失败策略、状态汇总、并发、超时、重试和恢复规则 |
| 权限与审批模型 | 双入口统一检查；操作影响与提权维度分离 | 授权范围、审批绑定、失效条件、自动执行清单与 Shell 边界 |
| AI Agent 边界 | 中心 Runtime；Observe / Suggest / Execute；主机 Agent 不运行 LLM | MVP 模型接入、上下文与秘密约束、建议验收和后续 Execute 边界 |

## 十二项设计检查清单

这些事项纳入架构设计，但按对应能力实施阶段确认，不要求 MVP 同时实现：

1. 资源关系、跨 Workspace 归属及 Host/Cluster 关联。
2. Task、Step、目标执行与 Attempt 的依赖和状态。
3. 结构化 Action、参数约束与 Shell 兜底边界。
4. 超时、掉线、重复消息、中心重启和安全重试。
5. Agent 一次性注册、重新绑定、克隆身份和凭据撤销。
6. Secret Store、任务临时使用、轮换与日志及模型隔离。
7. Observe、Suggest、Execute 的能力边界与默认行为。
8. 权限、风险、审批、执行授权的绑定与失效。
9. 操作原因、执行证据、前后状态和审计生命周期。
10. 配置 Diff、应用前快照、并发修改检测和受授权回滚。
11. Agent 签名校验、灰度、健康确认和失败回滚。
12. MVP 范围、后续阶段和真实链路验收条件。

上述五项核心设计和十二项检查项分布在功能与 design 文档中，实施时在对应文档记录结论，避免在此重复维护详细规则。项目 Git 资源与操作边界见[Git 管理](features/git.md)。
