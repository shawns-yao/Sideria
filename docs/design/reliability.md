# Redis、幂等、限流与并发控制

更新日期：2026-10-06  
状态：设计阶段，尚未实现和验证

## 定位

幂等、限流、有界队列和故障恢复属于 MVP 基础机制。中心引入 Redis 承担短期协调数据，PostgreSQL 保持任务、审批、身份和审计的持久事实来源。Redis 不取代数据库或 Agent 本地执行记录。

## 职责分配

| 数据或机制 | 位置 | 约束 |
| --- | --- | --- |
| Task、Step、目标执行、Attempt、审批、审计 | PostgreSQL | 持久化、事务和必要唯一约束 |
| API 幂等键与请求摘要 | PostgreSQL | 绑定用户、范围、Action 和规范化参数，保存对应任务及结果引用 |
| 执行去重与事实 | Agent 本地记录 | 执行副作用前记录接受事实，重连可查询；重启恢复需核对实际状态 |
| 登录、API、工具与 AI 请求速率 | Redis | 原子计数或令牌桶，配置有效期与作用域 |
| 短期查询缓存 | Redis | 标注目标与时间，不替代最终权限检查和新鲜数据 |
| 短期并发租约 | Redis | 仅辅助协调，需所有者校验、过期处理与执行端防并发 |
| 持久 AI 分析与证据引用 | PostgreSQL | 模型重试不能丢失调用和费用记录 |

当前 WebSocket 连接保存在所在中心进程内，不能把 socket 放入 Redis。初期单中心不需要消息总线；Redis Pub/Sub 不作为持久任务队列。

## 三层幂等

### API 受理

后台写请求携带客户端生成的幂等键。中心先认证和校验参数，再在数据库事务内登记请求和任务，建立必要唯一约束。

相同作用域、相同键、相同参数返回已有任务；同键不同参数返回冲突，不覆盖旧任务。用户有意再次执行同样操作应使用新的请求身份，不能永远按“参数相同”禁止合法重复操作。

幂等键的保留期、客户端重试窗口及过期后的行为需明确。查询已有任务仍需当前访问权限；已有幂等记录不赋予新权限。

### 调度投递

任务持久化成功后才下发。数据库存在待下发状态或投递记录，中心重启后扫描恢复；不能依赖内存队列或 Redis 临时消息作为唯一投递依据。

中心允许至少一次投递，重复投递使用相同目标执行 ID 与 Attempt ID。重新尝试生成新 Attempt，由操作定义和授权策略决定是否允许，不能与网络重发混同。

### Agent 执行

Agent 持久登记目标执行与 Attempt，重复消息返回已有状态。实际执行中可能在副作用发生后、结果落盘前崩溃，此时应标记待确认并核对目标状态，不能宣称严格 exactly-once。

本地记录损坏或丢失时停止自动重放不确定的写操作，返回状态缺失。可重复设置的配置也需检查版本；重启、删除、push 和外部安装不能套用通用自动重试。

## 并发与租约

冲突范围按资源定义，例如 Host+配置路径、Host+Git 工作目录、Host+Compose 项目、Cluster+工作负载。互不相关的查询不使用全主机大锁。

Redis 租约包含唯一所有者和有效期，释放与续期核对所有者。过期或失联不证明旧执行者已经停止，不能据此直接启动第二个破坏性操作。

Agent 对资源实行本地串行化，并核对中心持久化的执行代次或授权版本，拒绝过期任务。涉及跨执行者写入时，后续需定义 fencing token 的具体校验位置；不能只添加一个 token 字段就声称解决并发。

SSH 用户、外部 Git 或其他服务不受面板锁控制，文件摘要、HEAD、资源版本和应用原生锁仍需复核。

## 限流、限并发与预算

| 维度 | 策略方向 |
| --- | --- |
| 登录与注册 | 按来源、身份及令牌限制尝试，避免单一 IP 维度误伤共享出口 |
| 用户与 API | 按用户、目标、Action 限制请求速率，拒绝时返回明确重试信息 |
| 主机任务 | 按节点与操作类型限制并发；冲突资源进一步串行 |
| Agent 上报 | 认证后按节点限制批次、体积和积压，控制消息优先 |
| 文件与日志 | 限制传输并发、速率、单消息大小和跟随缓冲 |
| AI 分析 | 限制并发分析数、调用次数、上下文、总时长和费用预算 |
| 高成本读取 | 目录扫描深度、文件数、字节数和时长有界，可取消 |

限流不是权限检查；低频请求仍可能危险。速率限制、并发上限、超时和总预算分别定义。数值通过容量测试确认，不将建议值当成保证。

Agent 自身也有本地队列、速率和执行限制，不能仅依赖中心 Redis 防止资源耗尽。

## Redis 故障与恢复

Redis 仅供中心访问，凭据由部署环境注入，配置内存上限与各类数据过期策略，不缓存秘密明文。锁和限流状态不与可任意淘汰的缓存无区别混用；实例、容量分区或故障策略在部署时确定。

缓存失败可以回源，但必须保留本地并发限制，防止数据库被突发打满。登录、注册和高影响写任务的限制状态不可用时应拒绝或进入明确的保守模式，不能悄悄不限流执行。

Agent 已接受的任务按既定策略执行，Redis 故障不等于取消任务。Redis 恢复或数据被清空后，先核对 PostgreSQL 与 Agent 执行事实；新建锁不证明资源空闲。

## MVP 验收与待确认

覆盖重复提交、同键异参、数据库提交后中心崩溃、投递后确认丢失、Agent 执行中重启、Redis 重启、租约过期、限流拒绝和资源冲突。

分别验证“未重复受理”“未重复启动同一尝试”和“外部副作用是否确认”，不合并成一个幂等通过标志。

实现前确认 Redis 版本、数据隔离及内存策略、幂等保留期、限流阈值、降级策略、租约与 Agent 执行代次协议。数据库 schema 和具体 Redis 命令实现仍待设计。
