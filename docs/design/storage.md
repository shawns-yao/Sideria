# 数据存储与秘密管理

更新日期：2026-10-06  
状态：设计阶段，尚未实现和验证

## 数据与凭据

结构化数据统一使用 PostgreSQL，由中心管理数据库连接；大体积日志和传输临时文件独立存放。所有浏览器、主机 Agent 和集群连接器的数据访问通过中心 API，不直接连接数据库。

数据库连接配置由部署环境注入，仅供中心读取；数据库凭据不得进入 Agent 配置、前端资源、日志或 Git。

| 数据类别 | 内容与生命周期 |
| --- | --- |
| 服务器与能力 | 长期配置；解绑或归档不隐式删除历史任务 |
| 项目与 Git 工作目录 | 主机归属、登记路径和版本观测；历史观测不能冒充当前状态 |
| 集群与节点关联 | 集群身份、命名空间范围、Node UID 关联 |
| 凭据校验与秘密引用 | 注册令牌摘要、节点凭据摘要、受保护的秘密引用 |
| 指标 | 原始短期数据与聚合历史，按明确保留策略清理 |
| 任务与尝试 | 执行状态、结果和失败原因，保留重试历史 |
| 步骤与目标执行 | 步骤依赖、每个目标的结果及状态待确认记录 |
| 审批与执行授权 | 批准范围、有效期、撤销记录及关联尝试 |
| 告警与审计 | 异常、恢复和操作记录，不随服务器删除级联清除 |
| 配置版本与快照 | 受保护的修改前后版本和恢复引用，按保留策略管理 |
| 传输临时文件 | 只在需要中转或恢复时落盘，完成或过期后按策略清理 |

建议起始保留策略：原始指标 24 小时、分钟聚合 30 天；具体容量和查询性能需要验证。实时刷新不要求每次都持久化所有细粒度数据。

中心设置数据库连接池上限、连接与查询超时；指标写入采用有界队列和批处理，并验证 PostgreSQL 并发读写、历史查询与数据清理开销。达到实测容量边界后再评估独立时序存储；已确定的 Redis 用于限流、短期缓存和租约，不替代 PostgreSQL 指标与任务事实。

需要可恢复使用的中心秘密应加密保存，主密钥与数据库分开保管。备份需覆盖 PostgreSQL 数据、必要任务日志、配置和密钥恢复方式，并验证恢复流程；秘密不得进入 Git、前端资源、日志和交付包。

## Secret Store 与任务使用

SSH 私钥、Registry 密码、Git Token、云凭据、Kubeconfig 和模型 API Key 等作为 Secret 管理，与普通配置和任务参数分开。普通记录仅保存秘密引用；中心通过受保护的 Secret Store 获取值，按具体任务、目标和执行身份分发。

秘密使用链路为：授权检查 → 解析 Secret 引用 → 仅向需要该秘密的执行模块临时提供 → 完成或过期后按策略释放。模型仅接收完成任务所需的非秘密元信息；实际秘密值不进入 Prompt、工具返回、审计或普通日志。模型 API Key 仅供中心模型调用模块使用，不下发给主机 Agent。

任务授权不等于允许读取任意 Secret。需要明确访问范围、凭据版本、轮换和撤销行为；已交给外部程序的凭据不能仅凭删除中心记录就视为已撤销。临时文件采用受限权限并设清理规则，日志在持久化和提供给 AI 前脱敏。

## Redis 与持久数据的边界

Redis 的用途、过期、故障与幂等策略集中维护在[可靠性设计](reliability.md)。API 幂等键及参数摘要、任务投递和审批事实保留在 PostgreSQL；秘密明文不进入普通 Redis 缓存。

## AI 分析数据

保存分析目标、资源范围、工具调用引用、证据时间、模型配置版本、建议版本及关联任务。默认不把完整日志、文件或秘密复制到分析记录。

分析记录和模型服务端的数据保留分别配置。启用模型前确认数据外发范围；保留期限、删除行为、脱敏策略与模型提供方式尚待实施确认。

本文仅定义概念分类与生命周期，不提供未经 schema 确认的表结构或 SQL。
