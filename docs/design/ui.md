# 前端界面与视觉设计

更新日期：2026-10-06  
状态：视觉方向已确认，尚未实现或完成浏览器验证

## 1. 设计方向

Sideria 的视觉气质是“深夜天文台 + 精密仪器”：深色、克制、微弱光感、开放弧线、刻度、轨迹与真实数据变化。

用户提供的三张概念图用于参考信息结构和气氛，最新确认的单机仪表台方案优先。概念图中的数值、文案、功能、告警和硬件信息不是实际数据或自动生效的产品规则。

后续八张功能页参考图的取舍维护在[页面设计](pages.md)。视觉语言统一为“观测仪器 + 轨道秩序”，实现方案维护在[前端架构](frontend.md)。颜色、间距、字体、焦点、圆角与动效采用统一语义 Tokens；不按页面随意硬编码主题。

CPU / Memory / Disk / Network 必须保留，是单台服务器概览首屏的主角。使用不对称、按指标语义设计的区域，不以四张同尺寸、仅更换颜色与图标的矩形卡片作为最终方案。

## 2. 页面骨架

桌面端采用左侧导航、中间工作区、可收起的右侧 AI、按需展开的底部终端。导航支持访问服务器、项目、AI 分析、任务和设置；后续能力按实际实现开放。

服务器详情以主机身份、功能标签和仪表台为中心。多服务器总览仍可采用紧凑表格与行内趋势，不复制每台机器的完整大仪表台。

```text
主机页头：名称、连接状态、系统、规格、厂商/地区、运行时间
          地址、Agent 版本、数据新鲜度、终端 / 文件 / AI 入口
功能标签：概览 / 文件 / Docker / 项目与 Git / 终端 / 任务
┌────────────────────────────┬────────────────────────────┐
│ CPU                        │ MEMORY                     │
│ 开放式弧线 + 大数值         │ 用量尺度 + 大数值          │
│ 负载与真实短时趋势          │ 明确口径的分项与趋势       │
├──────────────────┬─────────┴────────────────┬───────────┤
│ DISK             │ NETWORK                  │ SYSTEM    │
│ 轨道刻度 + 容量  │ 上下行 + 双向趋势        │ 简明状态  │
│ 挂载点选择       │ 网卡与时间范围           │ 快捷入口  │
└──────────────────┴──────────────────────────┴───────────┘
下方按需展示：系统信息、事件、任务与详细趋势
底部终端：可调整高度、多标签、可全屏
```

CPU 与 Memory 占上方主要区域；下方 Network 获得更宽的曲线空间，Disk 展示容量，System Summary 保持紧凑。通过留白、对齐和细分隔组织整体，不使用卡片套卡片或每区独立发光边框。

## 3. Host Header 与状态点

- 名称、选定地址、地区、系统、CPU/内存规格、运行时间、Agent 版本应能快速辨认。
- 厂商和地区来自已知配置或可验证来源，不能根据 IP 或主机名猜测；多地址机器允许展开查看。
- 延迟显示必须注明测量含义，例如管理通道往返延迟，不能混同公网 Ping 或业务响应时间；未采集时不展示示例数字。
- 星体状态点用小型光点和少量轨迹体现品牌，旁边始终有文字状态。
- Agent 在线时允许极弱呼吸，失联或数据过期时停止在线动效；任务执行时可增加独立的细轨迹。
- 在线、任务执行和整体健康是不同状态。状态点的连接含义不能被任务动画覆盖；没有健康规则时使用“在线”，不宣称“Healthy”。

终端、文件和 AI 分析作为常用入口；重启、关机等高影响操作进入明确菜单与现有确认流程。页头不放大幅星球横幅、营销口号和与操作无关的装饰文字。

## 4. 四项指标的视觉语言

### CPU：开放式弧线与刻度

使用大号使用率、开放式弧线和少量刻度形成仪器感。弧线表达使用率，不用完整圆环或旋转装饰代替读数。附带逻辑 CPU 数量、明确时间窗口的负载与短时趋势。

温度仅在 Agent 确认传感器可用时展示；云主机无温度数据时显示不可用或省略该次要字段，不能填入示例中的 41°C。负载不等同于 CPU 百分比。

### Memory：空间占用与分层

突出已用/总量、百分比和水平用量尺度。分层可帮助理解占用，但不能用装饰立方体代替明确的数值关系。

App、Cache、Free、Available 等字段仅在采集定义明确时展示。分段条只使用互斥分类，不能将存在重叠的 Available 与 Cache 相加。使用率分子、分母和采集口径在监控文档及接口中一致维护。

### Disk：克制的轨道尺度

轨道、弧线或刻度表现容量比例，中央或相邻位置保留百分比与已用/总量。用单一轻量轨迹呼应巡星，不绘制夸张土星、复杂立体透视或持续绕行粒子。

显示当前挂载点并允许切换。多挂载点不简单累加为可能重复的“全机磁盘”。System、Docker、Logs、Other 分类仅在按需分析具有明确分类和去重结果后显示；首版不能为了填满界面定时扫描整盘。

### Network：真实的双向变化

下载与上传分别显示数值、方向和单位，曲线使用相同速率单位。时间悬停显示同一采样时刻的上下行，可通过键盘聚焦或触摸取得同等信息。

接收/发送用线型、标签或标记区分，可使用非状态性的细微明度差；警告色只表达已判定异常，不能因一次尖峰直接变红。曲线按真实采样更新，不生成假波动或通过平滑隐藏异常峰值。

今日累计流量须有明确时区、日界线、接口范围与完整性。尚无连续统计时不显示伪造的“今日流量”；不是服务商账单数据。

## 5. 颜色与状态光

正常状态以中性底色、清晰文字和安静的仪表为主，不为每项指标铺绿色背景。颜色主要表达状态，不建立“CPU 永远蓝、Memory 永远紫、Disk 永远黄、Network 永远绿”的映射。

| 用途 | 设计约束 |
| --- | --- |
| 页面背景 | 深色起点为 #0B0D12 |
| 仪表区域 | 面板起点为 #11141B，低对比边界；交互控件仍需足够可辨认 |
| 主要操作 | 统一克制的冷色强调，避免各模块自建主题色 |
| 正常 | 中性数据与少量状态提示，不整区着色 |
| 接近阈值 / 警告 | 局部刻度、读数或状态标记转暖，并附原因和持续时间 |
| 严重异常 | 明确错误文字与局部强调，不用全屏闪烁 |
| 未知 / 过期 / 失联 | 明确文字与静态视觉，不显示为正常或零值 |

示例中的 75%、94%、52% 都不是默认告警阈值。状态依据配置的规则、持续时间、数据新鲜度和适用对象判断；尚无规则引擎时只显示事实，不伪造自动健康评级。

背景允许极低密度、静态的点状纹理，集中在标志或页头留白，不覆盖数值、曲线、表格、文件和日志。默认不铺银河、不使用渐变球、bokeh 或强烈发光边框。

以上色值是深色主题起点，最终文字、焦点、图表和控件对比度需实际验证。未来浅色主题沿用同一信息层级与状态语义。

## 6. System Summary 与数据完整性

System Summary 只保留 Docker 容器、已支持的系统服务、活动任务、告警等少量摘要和入口。例如容器需写清“运行 8 / 总计 8”，服务数需明确统计范围。

未接入的服务采集和告警能力显示未配置/不可用或不渲染该项，不填 0，也不为摘要新增未计划的子系统。AI 面板打开时，摘要可折叠，但四大指标仍需保留。

趋势目标视窗可使用最近 30 分钟；这是产品展示目标，保留方式与性能仍需确认。只有 5 分钟数据时如实显示覆盖范围，缺失区间留空并说明，不补成完整曲线。

## 7. AI 与底部终端

右侧 AI 可展开、收起、调宽或转为独立分析页。保持目标范围可见，按工具进度、已知事实、证据、推断和建议组织内容；不随页面切换隐式改变分析对象。

AI 面板不能把仪表台挤成不可读的细列。宽度不足时切为覆盖抽屉或独立页，用户显式打开后可暂时覆盖工作区。建议采纳进入已有权限和任务流程。

底部终端可折叠、拖动高度、多标签和全屏，标签明确服务器/容器、Shell 和执行用户。收起面板不等于结束会话，结束动作和断线行为遵循[终端设计](../features/terminal.md)。Linux 使用实际安装的 Shell，不将“PowerShell 式面板”误解为所有机器必须安装 PowerShell。

## 8. 响应式、动效与可操作性

- 桌面参考尺寸为 1440×900 和 1920×1080：AI、终端收起时，四大指标与核心读数在首屏可见。具体列宽通过实现验证，不硬编码到所有屏幕。
- 中等宽度先调整下方分区，保留 CPU/Memory 层级；窄屏按 CPU、Memory、Disk、Network、System 顺序纵向排列，允许滚动而不缩小到不可读。
- 在 390×844 等移动尺寸验证布局；导航与 AI 使用抽屉，终端支持全屏。移动端不强求所有指标同时塞进首屏。
- 数值采用稳定宽度和清晰单位，路径、命令与提交 ID 用等宽排版，中文优先可读性。
- 图标使用一致的线性图标库，优先 lucide；用户界面不直接使用 Emoji。
- 数据刷新不重置滚动、选择和键盘焦点；交互状态不能只靠颜色或 hover。
- 状态呼吸与任务轨迹极弱且可关闭；遵循 prefers-reduced-motion，减少动态时保留文字和静态状态。
- 后台或不可见图表暂停无意义动画；优先轻量 SVG/CSS，不为该页面默认引入 WebGL 或持续粒子渲染。

## 9. 实现与验收边界

先以组件方式实现页头、CPU 仪表、Memory 用量、Disk 轨道、Network 曲线、System 摘要、AI 侧栏和终端面板。展示组件与数据采集、状态判断分离，不在图表组件中硬编码告警阈值。

使用已有 Vue 3 + TypeScript 方向；具体组件库尚未正式确定。可以复用基础表格、菜单、抽屉与表单，但仪表台按本设计定制，不让组件库默认四卡布局决定产品外观。

浏览器验证覆盖桌面和移动端、键盘焦点、减少动态、长名称、多地址、不同挂载点、空数据、部分历史、失联、未知、警告、AI 展开和多终端切换。验收用模拟状态时必须标记为 UI 测试数据，随后另做真实数据链路验证。

当前只完成文档设计，未创建界面、运行项目或验证截图。后续视觉验收需在获得项目运行授权后执行。
