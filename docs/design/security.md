# 权限、风险与审批

更新日期：2026-10-06  
状态：设计阶段，尚未实现和验证

## Action 影响与权限维度

`Read / Write / Destructive / Privileged` 用于描述动作边界，不是四个互斥等级。Read、Write、Destructive 表达操作影响；Privileged 表达额外权限要求，可以与前者组合。

| 操作示例 | 影响与权限考虑 |
| --- | --- |
| 查看容器日志 | Read；仍需目标范围和敏感内容权限 |
| 修改系统配置 | Write；依路径可能需要 Privileged |
| 删除容器或文件 | Destructive；核对具体目标、数据影响及可恢复性 |
| 重启容器或系统服务 | Write；存在业务中断影响，部分操作需要 Privileged |
| 修改防火墙 | Write + Privileged；还可能切断管理通道 |

权限判断结合用户身份、Workspace、目标资源、Action、参数范围、执行身份及实际影响。审批不能授予用户原本不具备的权限；允许 AI 执行也不能替代目标机器的实际权限校验。

## 权限、风险、审批与执行授权

统一链路为：Action → 参数校验 → Permission Check → Risk Check → 必要 Approval → 执行授权 → Agent 或连接器执行。

可以参考 TaskGrant / HITL 的思路：授权绑定具体任务或步骤、Action、目标、参数摘要、秘密引用及版本、有效期和次数范围；HITL 在需要时由用户审查具体操作。这里借鉴概念，不假定已复用其他项目的实现。

批准后的目标、参数、秘密版本或必要前置状态发生变化时，重新检查并在需要时重新审批。下发和重试前复核授权有效性；授权撤销或过期阻止后续执行，但不能保证已经开始的外部操作被撤销。

策略可以允许日志查看自动进行，也可以允许特定范围内的容器重启；删除、文件覆盖和防火墙修改等高影响操作默认要求确认。具体可自动执行的 Action、资源范围和条件在开放相关能力前明确。

## 基础保护

- 所有 HTTP 和 WebSocket 操作校验用户、节点和任务作用域。
- TLS 校验不能默认关闭；使用 SSH 安装时核验主机密钥。
- Agent 权限决定实际操作边界，不把“连接成功”视为“拥有全部权限”。
- 基础监控优先低权限运行；安装、服务管理等通过明确提权策略开放。
- 普通文件浏览遵循执行身份的权限，不默认允许读取所有系统秘密。
- Docker socket 访问具有很高的宿主机控制能力，应独立授权。
- 文件覆盖、删除、批量修改和集群变更显示目标及影响，再执行确认后的操作。
- 日志脱敏、长度限制和终端访问控制属于基础功能。
- Agent 升级使用经过校验的发布包，保留版本信息和失败处理方案。

## AI 模式与授权关系

AI 的 Observe / Suggest / Execute 行为定义统一维护在[AI 功能文档](../features/ai.md)。模式限制、用户权限、目标执行权限和执行授权同时生效。MVP 的 AI 仅开放 Observe/Suggest，不能调用任意 Shell 或通过网页终端绕过限制。

一次确认应绑定可审查的具体目标、参数和影响。用户在面板中已完成符合策略的确认时，不为同一动作叠加一层内容相同的“AI 审批”。具体交互与授权有效范围需在相关写操作开放前明确。

日志、文件、网页和工具结果是待分析数据，不是指令来源；其中的文本不能扩大目标范围、获得 Secret 或触发未经授权的操作。
