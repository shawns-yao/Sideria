# 终端与 SSH

更新日期：2026-10-06  
状态：设计阶段，尚未实现和验证

- 终端由 Agent 创建 PTY，中心转发，前端使用 xterm.js。
- Agent 终端是远程 shell，不应标成 SSH 会话；独立 SSH 接入另行实现。
- 宿主机终端与 Pod/容器终端明确标识，不混淆执行环境。

## 会话流程

用户选定服务器 → 中心核验终端权限 → Agent 创建指定身份的 PTY → 浏览器通过中心收发数据 → 关闭会话或按超时策略清理。

会话记录目标、用户、执行身份、建立和结束时间；不得默认把完整输入输出长期录制或提供给 AI。日志及录屏策略需要单独确认。

## 底部终端面板

采用可收起、可调整高度、支持多标签和全屏的底部终端。服务器详情可直接打开；文件页面支持在选定目录打开，仍校验路径与权限。标签与当前会话明确展示服务器或容器、实际 Shell、执行用户和连接状态。

保留复制粘贴、Ctrl+C、窗口尺寸调整和显式结束会话。收起面板不等于结束会话；断线不能自动重发上一条命令。AI 只分析用户明确选中且允许提供的内容，建议命令不直接写入终端执行。

“PowerShell 式面板”描述交互体验；Linux 使用实际可用的 Bash、Zsh 等 Shell。Windows Agent 和 Windows PowerShell 接入不是首版范围。布局与响应式遵循[前端界面设计](../design/ui.md)。

## SSH 的位置

SSH 用于可选首次安装和独立故障排查，凭据进入 Secret Store，连接时核验主机密钥。主机 Agent 在线操作不依赖长期保存 SSH 私钥。

## MVP 与边界

MVP 的终端供已授权用户直接操作。它属于任意命令执行入口，不能仅凭打开页面就取得权限。AI Observe/Suggest 不得借终端执行命令。

浏览器断线后的 PTY 保留、重连期限和清理策略须明确；后台任务的持久性不能自动套用于交互终端。

## 验收

验证输入输出、窗口调整、权限拒绝、会话关闭、网络断开和目标隔离。页面切换服务器不得把旧终端输入发往新主机。
