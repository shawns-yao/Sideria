# Docker 与 Compose

更新日期：2026-10-06  
状态：设计阶段，尚未实现和验证

- 容器列表、状态、资源、日志、启动、停止、重启和终端。
- 展示镜像、端口、挂载路径，支持跳转到相关宿主机目录。
- 优先使用本机 Docker Engine API，并协商 API 版本。
- Compose 管理保存项目目录、配置文件及变量引用，调用受支持版本的 Compose CLI。
- 管理界面只操作明确归属的独立 Docker 资源，不通过底层运行时干预 Kubernetes 工作负载。

## MVP

支持独立 Docker 主机的容器列表、状态、近期日志、资源和基本启停操作。普通查询使用轻量请求；重启等修改操作进入可追踪任务。日志进入 AI 前限制条数、字节数与时间范围并脱敏。

## Compose 后续流程

选择主机与已有项目目录 → 检查配置、挂载目录、权限、端口和网络 → 展示计划及影响 → 受授权拉取与部署 → 验证运行状态和已配置的健康检查。

部署完成、容器进程运行和业务健康是不同结论；没有业务检查时不宣称应用正常。

## 验收

验证无 Docker、无 socket 权限、API 不兼容、容器退出与日志缺失。通过 UI 执行基本操作并复核实际结果；AI 分析必须引用正确主机与容器的证据。

Compose 后续覆盖缺失目录、环境变量、仓库不可达、下载失败和部署中断。
