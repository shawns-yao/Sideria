# AI 状态分析、诊断与建议

更新日期：2026-10-06  
状态：设计阶段，尚未实现和验证

## 定位与 MVP

AI 是 Sideria 不可或缺的核心功能，从 MVP 起接入真实工具和实际服务器数据。它帮助用户理解状态、调查原因和选择处理方式；基础面板提供直接、确定性的操作入口。

首版开放 Observe/Suggest：服务器概览、单机资源诊断、Docker 近期日志解释、已登记项目的 Git 状态比较，以及基于已知信息的部署目标建议。专项代理探测、Compose 部署及 Kubernetes 分析随对应工具后续开放，不把未实现能力写成已完成检查。

首版不开放 AI 自主修改。用户可以转到已有 UI 发起明确操作，执行仍走权限、确认和任务链路。后续 Execute 使用同一结构化工具，不新建一条模型直连 Agent 的通道。

## 输入与证据

输入包含用户目标、显式目标服务器或项目范围、应用需求和已授权读取上下文。模型可以主动请求相关读取工具，不能自行扩大到未授权主机、路径或 Secret。

每条证据保留目标资源、工具调用 ID、采集时间、范围、结果及数据缺口。使用结构化指标、近期样本、受限日志和 Git 状态，不仅凭截图或单次 CPU 数值下结论。

## 调查流程

用户明确目标 → 中心创建分析记录 → AI 选择已注册读取工具 → 权限与成本检查 → Agent 或中心提供结果 → AI 形成解释和建议 → 用户查看证据、继续检查或发起具体操作。

调用次数、总时长、扫描深度、文件数量、日志体积与模型上下文均有上限。高成本读取需按策略确认或收窄范围；预算耗尽、工具失败、权限不足时返回已知结果与未完成项。

## 建议的输出结构

- 已知事实：哪些指标、日志和项目状态已实际取得，来自何时、哪个目标。
- 推断与不确定性：可能原因、支持证据、冲突证据和其他解释。
- 建议动作：明确目标、参数或待补参数、预期效果、影响及所需权限。
- 待检查项：缺少的应用需求、容量、端口、目录或网络证据。
- 执行状态：未执行、已由用户发起任务、实际结果；生成建议不等于完成操作。

不要求模型编造数值置信度。工具无法确认时使用“候选”“可能”“未验证”等明确状态。

## 首版场景

| 用户问题 | 证据与回答边界 |
| --- | --- |
| 哪台服务器需要关注 | 比较选定机器当前指标、短窗口与数据新鲜度；不虚构长期趋势 |
| 服务器为什么变慢 | 先看资源、相关容器状态与可用日志；区分观察到的瓶颈和未证实根因 |
| 磁盘怎么处理 | 查看挂载点和授权范围内目录信息，提出候选清理对象；不自动删除 |
| 容器为什么退出 | 读取退出状态与近期日志，报告证据与下一步，不自动重启 |
| 各服务器项目在哪个分支 | 查询已登记项目的分支、HEAD、dirty 和本地上游状态，标明远端新鲜度 |
| 应用部署到哪里 | 根据应用需求、架构、余量、已有运行环境和已验证网络信息给出候选；缺项时询问或标明假设 |

## 模式与用户交互

| 模式 | 行为 |
| --- | --- |
| Observe | 调用已授权读取工具，解释状态与证据 |
| Suggest | 在读取基础上提出可审查计划和建议，不执行写操作；MVP 的建议入口默认使用此模式 |
| Execute | 后续开放；在既有权限与明确授权范围执行，满足策略要求的审批 |

入口既包括独立分析页面，也包括服务器“分析状态”、容器“分析日志”、项目“分析 Git 状态”。目标范围始终可见；切换页面不悄悄改变已发起分析的目标。

用户采纳建议时先复核状态和方案版本，再形成具体操作。原建议因时间或目标变化而过期时应重新检查，不沿用过期审批。

## 模型与秘密边界

已确认优先采用 OpenAI 兼容的 Responses API（`/v1/responses`）。中心配置 API 基址、模型名称和秘密引用，浏览器不直接请求提供方。首版要求实际验证文本输出、流式事件、函数工具调用及工具结果回传；第三方宣称“OpenAI 兼容”不能代替这些验收。

不默认回退到 Chat Completions，也不使用占位回答伪装成功。模型、工具或流中途失败时，分析记录标明未完成并保留已取得的证据；工具调用按调用 ID 去重和关联。主动取消与预算耗尽均终止后续调查。提供方数据保留与外发许可独立确认，兼容接口不代表相同隐私政策。

模型在中心接入，主机 Agent 不运行 LLM。模型凭据只交给中心模型客户端；模型上下文不包含真实 Secret。工具结果在提供给模型前实施访问控制、范围限制和脱敏。

日志、源码注释、文件及 Git 提交信息均为不可信数据，不是新指令；不能据此绕过权限或触发写操作。敏感文件类型、允许外发数据及提供方保留政策在实际模型接入前确认。

模型不可用时说明分析未完成，保留已采集证据；基础面板和已授权任务继续可用，但不能以降级结果宣称 AI 验收通过。

## 验收

必须经过真实用户入口、中心 AI Runtime、模型调用、结构化工具及真实 Agent 查询。模拟工具只用于局部测试，不作为 AI 能力验收。

预设正常状态、异常日志、陈旧指标、缺失权限、dirty Git 工作区、远端状态未知、提示注入文本和模型失败场景。核对事实与证据一致、目标不越界、不泄密、不擅自写入和建议可操作性。

报告有效样本、可评分输出、成功、失败与未执行样本；区分工具链路正确与诊断质量。具体样本、评分标准、模型版本和阈值在验收前确定，不能用“能聊天”作为完成标准。

## 待确认

具体提供方与模型、兼容性、数据外发范围、模型上下文与调用预算、短窗口长度、建议评分及后续 Execute 授权策略。接口方向已确定为 Responses API。AI 不后置到可有可无的插件阶段。
