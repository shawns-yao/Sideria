# 代理与网络诊断

更新日期：2026-10-06  
状态：设计阶段，尚未实现和验证

代理检查区分以下范围：Agent 自身、宿主机命令或服务、Docker daemon、构建过程、容器内应用、Kubernetes 节点运行时。

检查结果记录探测发起位置、目标、时间、直连/代理方式与错误证据。代理可达不等于实际下载过程使用该代理；不能将所有超时归因为代理故障。

## 功能流程

用户选择主机、访问目标及检查范围 → 工具读取可识别的相关配置摘要 → 从目标主机执行有界 DNS、连接及 HTTP 检查 → 比较直连与指定代理结果 → AI 解释证据和未确认事项。

检查需区分超时、解析失败、认证、证书和仓库响应等错误。配置存在、代理可达、应用实际使用该代理分别记录。代理口令和带凭据地址不进入普通结果。

## 实施阶段

专项网络探测、代理诊断和代理配置写入在 MVP 后开放。MVP 的 AI 可以解释已有错误日志，但不能声称已经完成尚不存在的探测。

代理修改与服务重启分别授权，提前说明对 Agent 管理连接和业务连接的影响。

## 验收

覆盖直连失败但代理成功、代理不可达、认证失败、配置未加载和采样信息不足；验证 AI 不把未知原因判成已确认的代理问题。
