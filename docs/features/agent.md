# 服务器接入与 Agent

更新日期：2026-10-06  
状态：设计阶段，尚未实现和验证

## 注册流程

1. 用户在中心创建待接入服务器，填写名称和标签。
2. 中心生成绑定该接入流程的短期、一次性注册令牌。
3. 用户在目标机器执行安装程序，或授权中心通过 SSH 安装。
4. 安装程序检测系统和架构，上传或下载匹配的预编译 Agent，并配置 systemd 服务。
5. Agent 经 HTTPS 注册，换取该服务器独立的长期凭据。
6. Agent 主动建立经过认证的长连接，报告版本、系统信息、网卡地址和能力。
7. 中心显示接入结果，以及每项能力的可用状态。

注册令牌仅用于接入。长期凭据支持单机撤销和轮换，不同机器不共用一个全局令牌。中心根据认证身份确定服务器归属，不能仅信任消息中自报的服务器 ID。

重新注册必须明确是重新绑定原 Host 还是创建新 Host，并撤销被替换的旧身份。克隆机器不能继续共用复制的凭据；凭据失窃时撤销对应身份，终止连接并阻止后续任务下发。已开始的外部操作仍需查询状态，不能因撤销凭据而宣称已取消。

建议初版使用 TLS 加每节点独立随机凭据。中心保存凭据校验摘要，Agent 在权限受限的本地文件中保存凭据。实施时明确轮换、过期和重放处理；不将凭据放进 URL、日志或前端可见配置。

## 地址与服务器身份

- 使用稳定的 `server_id`，IP 不是主键。
- 同一服务器可以记录多个 IPv4、IPv6 和人工配置的管理地址。
- Agent 上报的接口地址、中心观察到的连接来源地址和 SSH 管理地址分别记录。
- IP 变化不自动创建新服务器；主机名相同不自动合并服务器。
- 重装或克隆后的重新绑定需明确处理，避免复制 Agent 凭据造成身份冲突。
- Agent 身份、SSH 主机密钥、Kubernetes Node UID 是不同对象，不混用。

## 安装与网络要求

受管服务器需要能够访问中心的注册和长连接入口。建议初版采用 HTTPS/WSS，gRPC 双向流作为选型比较项；最终传输协议在实现前确认。双向任务通信复用 Agent 主动建立的连接，不要求开放额外 Agent 入站端口。

提供在线安装和离线发布包。SSH 自动安装可以由中心直接上传二进制，避免目标服务器依赖 GitHub 下载或现场编译。SSH 安装仍要求中心能到达目标 SSH 地址；Agent 出站接入不会自动解决 SSH 可达性。

Agent 连接中心的代理设置独立于宿主机、Docker、构建任务和应用代理。修改代理配置时不得意外切断管理通道。

## Agent 更新机制

升级作为受授权任务管理：选择版本和目标 → 小批验证与灰度 → Agent 获取匹配发布包 → 使用可信发布密钥校验签名和完整性 → 保留旧版本并安全替换 → 重启 → 核对版本、连接和基本能力 → 报告结果。

升级前检查系统架构、协议兼容、空间和正在执行的任务，明确排空或延期策略。自动回滚旧二进制只在已设计并验证的条件下执行；本地状态或协议发生不兼容变化时，不能承诺替换旧二进制即可恢复。中心连接中断期间也需能在本机判断升级健康。

可信发布密钥、升级发起权限、批次停止条件、兼容窗口与回滚机制在批量升级能力实施前确认。首版可以采用受控人工更新，不要求一次完成完整灰度平台。

## 执行职责与能力

主机 Agent 是受控执行器，负责本机指标采集、文件、终端、Docker、已登记项目的 Git 查询及经授权的系统操作；不运行 LLM，不理解自然语言，不自行扩大权限。Agent 根据本机环境报告可用能力及不可用原因，收到请求仍检查身份、能力、参数、授权和本地权限。

## 首版与验收

MVP 包含注册、认证、心跳、能力报告和断线重连。两台真实服务器分别接入，验证身份隔离、凭据撤销、重复连接和重装绑定。连接中断不应影响原有业务。

Agent 升级先采用受控人工更新，完整签名发布、灰度和回滚按后续阶段实现。协议选型和消息兼容在通信设计中维护。
