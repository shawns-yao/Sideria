# 服务器项目与 Git 管理

更新日期：2026-10-06  
状态：设计阶段，尚未实现和验证

## 目标与资源

在同一面板查看每台服务器上已登记项目的 Git 状态，并在明确授权后执行 Git 操作。AI 可读取这些状态给出部署、同步和改动处理建议。

同一远端仓库在不同服务器或不同目录的 checkout 是不同项目工作目录，不能只用远端 URL 合并。项目记录稳定 project_id、所属 Host、用户指定路径及 Git 根目录；分支、HEAD 和工作区状态是实时查询结果，不作为固定身份。

## 项目接入

用户选择服务器并登记项目目录。Agent 核验路径、访问权限、Git 可执行程序和实际仓库边界。发现 Git 根目录在指定目录之外时明确提示，不静默扩大操作范围。

允许在用户指定的有限根目录内发现候选项目，限制深度、数量和扫描时间；不默认扫描整台机器，不自动读取所有项目内容。不硬编码 .git 必须是目录，需识别 worktree 的 .git 文件。裸仓库、子模块和 worktree 如尚未支持写操作，应只展示识别结果和限制。

## MVP：状态读取

- 当前分支、HEAD 提交、detached HEAD、空仓库等状态。
- 本地分支、已有的远端跟踪分支及上游配置。
- 暂存、未暂存、未跟踪、冲突文件的数量和按需列表。
- 最近提交摘要；Diff 按指定文件或范围读取，限制体积并处理敏感内容。
- 已配置远端的脱敏信息，以及根据本地跟踪引用计算的 ahead/behind。
- 当前查询时间、最后由本面板记录的成功 fetch 时间（若有）和信息局限。

本地远端跟踪引用不保证等于远端当前状态。“领先/落后”必须标明比较对象；没有上游或没有可比较提交时显示无法比较。读取分支不自动 fetch，未跟踪文件不默认读取内容并发送给模型。

优先使用 Git 机器可读输出及明确参数，例如 status 的 porcelain 格式和 ref 查询；设置避免非必要锁和交互提示的执行环境。使用参数数组、参数边界及路径校验，不拼接用户输入成 shell，也不自动更改全局 safe.directory 配置绕过所有权检查。

## 后续：受控 Git 操作

| 操作 | 影响与前置检查 |
| --- | --- |
| fetch | 联网、凭据使用、更新本地对象和引用；是写任务，不能当作普通状态读取 |
| clone | 写入目标目录，检查路径、已有内容、空间、远端和凭据 |
| 切分支 / 创建分支 | 检查分支存在性、工作区、冲突及 worktree 占用，不自动丢弃改动 |
| pull / merge / rebase | 明确来源和合并策略；可能更改文件与历史、触发冲突和 Git hook |
| commit | 展示实际暂存内容，限定文件范围与作者配置，不自动 add 全部文件 |
| push | 明确远端与分支、待推送提交及授权；提交授权不涵盖推送 |
| reset / clean / 强制推送 | 不属于初期 Git 操作范围；以后另行设计恢复性、影响和明确审批 |

写操作采用 Task，执行前复核 HEAD、分支和工作区状态，防止建议生成后用户已通过 SSH 修改仓库。Git 锁、外部进程和服务器权限仍需处理；中心串行化不保证仓库不会被外部修改。

dirty 工作区不是自动清理理由；冲突需要报告和用户处理，不自动 stash、reset 或覆盖。网络中断后先核对引用或远端结果，不能盲目重试 push。Git hook 属于潜在执行入口，启用相关写操作前明确其行为和授权。

## 与 AI、部署的关系

AI 可以回答“各服务器项目分别在哪个分支”“哪些项目有未提交改动”“候选机器是否适合更新”，并引用服务器、项目、HEAD、时间和工具结果。

目录中的 Git HEAD 不证明当前进程或容器使用该版本。只有存在经验证的构建、镜像或发布记录时才能关联部署版本；否则明确“仓库版本已知，实际运行版本未核实”。

模型只接收授权且脱敏的状态或局部 Diff。Git Token、SSH 私钥和含凭据 URL 不进入模型、日志或前端普通状态。

## 验收与待确认

MVP 在两台真实服务器登记项目，验证不同分支、dirty、detached HEAD、无上游、空仓库、权限不足及相同远端不同工作目录。验证查询不执行隐式 fetch 或修改仓库配置。

后续写操作分别覆盖前置状态变化、冲突、凭据失败、hook、断线和错误目标拒绝。Git 操作对象、支持版本、hook 策略及仓库恢复方式在写功能实现前确认。
