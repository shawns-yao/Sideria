# 服务器状态与网络监控

更新日期：2026-10-06  
状态：设计阶段，尚未实现和验证

- 展示 CPU、内存、Swap、负载、运行时间、各挂载点容量与 inode。
- 展示每张网卡的接收/发送速率、累计字节和采样时间。
- 建议基础指标每 5～10 秒采样，具体通过测量调整。
- 上下行速率由累计字节差值除以真实采样间隔计算。
- 重启、网卡重建或计数回退时重建基线，不产生负速率或虚假流量峰值。
- 总流量明确选择统计网卡，避免物理网卡、网桥、隧道和虚拟网卡重复计算。
- 月度流量须配置周期并披露采集缺口；网卡统计不等同于服务商计费流量。
- 分别显示最后采集时间和最后接收时间，采集失败不填零。

收不到心跳首先表示 Agent 失联，不直接证明服务器关机。Kubernetes Node Ready、主机 Agent 在线、Docker 可用和应用健康分别展示。

## 页面与 AI 数据

总览展示各服务器的资源、上下行、连接状态、采样时间和异常；详情按时间范围查看可用指标。AI 获取结构化数值、时间、采样窗口及缺口，不仅接收图表截图。

MVP 提供当前状态和有界短窗口样本。单机仪表台的目标视窗为最近 30 分钟，实际保存方式和资源预算仍待性能验证，不要求先完成完整历史趋势平台。窗口不足时展示实际覆盖范围，缺失区间留空，不伪造历史或判断长期趋势。

## 单机仪表台的数据约定

- CPU、Memory、Disk、Network 是首屏核心指标；开放弧线、空间尺度、轨道和动态曲线的布局维护在[前端界面设计](../design/ui.md)。
- CPU 温度属于可选传感器数据，不支持的云主机不能填入示例温度。负载需标明时间窗口，与使用率区分。
- 内存占用使用一致的采集口径；App、Cache、Free、Available 不假设互斥。堆叠分项必须有可验证的分类关系，不重复相加。
- 磁盘显示实际选定挂载点；System、Docker、Logs、Other 需要受限且有明确分类和去重的分析，不通过常驻整盘扫描填充图表。
- 今日上下行统计明确时区、接口和数据完整性；尚无完整统计时显示不可用或部分数据。
- 突发流量和单次高占用不自动构成告警。颜色与持续时间依据实际规则，未配置规则不输出伪造的健康结论。
- 主机连接、Agent 数据新鲜度、容器运行和应用健康分别判断；摘要中的未知数据不填零。

## 验收

在两台真实服务器核对 CPU、内存、磁盘和选定网卡的统计口径。覆盖重启、计数回退、Agent 失联、延迟上报和虚拟网卡重复计数。采集数据的准确性与 AI 对数据的解释分别验证。

补充无温度、内存分项重叠、多挂载点、部分历史及日流量缺口场景。视觉测试与指标准确性验证分别报告，不能用概念图数值作为真实采集结果。
